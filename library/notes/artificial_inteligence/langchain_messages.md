## TL;DR
LangChain support four types of messages: `System`, `Human`, `AI`, and `Tool`. Each message type represents one participant of the interaction loop.
You can provide more context to a specific message type according to provider availability and it's also possible to share multimodal data based on the `ContentBlocks`.
# LangChain Messages
Fundamental unit of context for models in LangChain. They represent the input and output of models, carrying both the content and metadata needed to represent the state of a conversation with a [LLM](large_language_models.md).

LangChain provides a standard message type that works across all model providers.

Messages are object that contain:
- **Role**: Identifiers one of the message types:
	- **System**: Tells the model how to behave and provide context for interactions.
	- **User**: Represents user input.
	- **AI**: Response generated by the model, including text content, tool calls, and metadata.
	- **Tool**: Represents outputs of tool calls.
- **Content**: The content of the message like text, image, audio, documents, etc.
- **Metadata**: Optional fields such as response information, token usage etc.
## Message content
It's the payload of data that get's sent to the model. 
### Provider specific format
Messages' `content` attribute is loosely-typed supporting strings and object lists, allowing support for provider native structures, such as multimodal content and other data.
```python
from langchain.messages import HumanMessage

# String content
human_message = HumanMessage("Hello, how are you?")

# Provider-native format (e.g., OpenAI)
human_message = HumanMessage(content=[
    {"type": "text", "text": "Hello, how are you?"},
    {"type": "image_url", "image_url": {"url": "https://example.com/image.jpg"}}
])
```
### Standard content blocks
A standard representation for message contents that works across providers.

It can be provided as input for the message:
```python
# List of standard content blocks
human_message = HumanMessage(content_blocks=[
    {"type": "text", "text": "Hello, how are you?"},
    {"type": "image", "url": "https://example.com/image.jpg"},
])
```

>Specifying `content_blocks` when initializing a message will still populate message `content`, but provides a type-safe interface for doing so.

It can also be extracted from a provider specific message:
```python
from langchain.messages import AIMessage

message = AIMessage(
    content=[
        {
            "type": "reasoning",
            "id": "rs_abc123",
            "summary": [
                {"type": "summary_text", "text": "summary 1"},
                {"type": "summary_text", "text": "summary 2"},
            ],
        },
        {"type": "text", "text": "...", "id": "msg_abc123"},
    ],
    response_metadata={"model_provider": "openai"}
)

print(message.content_blocks)
#[
#	{'type': 'reasoning', 'id': 'rs_abc123', 'reasoning': 'summary 1'},
#	{'type': 'reasoning', 'id': 'rs_abc123', 'reasoning': 'summary 2'},
#	{'type': 'text', 'text': '...', 'id': 'msg_abc123'}
#]

```

>Standard content blocks are represented as a list of typed dictionaries. Each item in the list must adhere to the specified [reference](https://docs.langchain.com/oss/python/langchain/messages#content-block-reference)

>If an application outside LangChain needs access to standard block representation, you can opt-in to storing content blocks in message content. To do this you can initialize any chat model with `output_version="v1"`.

```python
from langchain.chat_models import init_chat_model
model = init_chat_model("gpt-5-nano", output_version="v1")
```
## Understanding
LangChain messages are a standard interface that provide structured access to messages sent and received from the model along side any relevant metadata. It supports provider specific formats as well as standard ones and we can send not only text but multimodal data.
## When to Use
### Text Prompt
Use when:
- You have a single standalone request.
- You don't need conversation history.
- You want minimal code complexity.
- Ideal when you don't need to retain conversation history.
```python
response = model.invoke("Write a haiku about spring")
```
### Message Prompts
Use when:
- Managing a multi-turn conversation.
- Working with multimodal content (images, audios, etc).
- Including system instructions
```python
from langchain.messages import SystemMessage, HumanMessage, AIMessage

messages = [
    SystemMessage("You are a poetry expert"),
    HumanMessage("Write a haiku about spring"),
    AIMessage("Cherry blossoms bloom...")
]
response = model.invoke(messages)
```
## Failure Modes
- Using provider specific implementations can cause issues if you need to swap vendor's. If you need to use provider specific message, you can create an abstraction layer on top of it so that you can update your provider without having to update all messages across your system.
## Implementation (Practical)
### Basic usage
```python
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage, AIMessage, SystemMessage

model = init_chat_model("gpt-5-nano")

system_msg = SystemMessage("You are a helpful assistant.")
human_msg = HumanMessage("Hello, how are you?")

# Use with chat models
messages = [system_msg, human_msg]
response = model.invoke(messages)  # Returns AIMessage
```
### Dictionary format
```python
# Open AI chat completion format, same for all providers.
messages = [
    {"role": "system", "content": "You are a poetry expert"},
    {"role": "user", "content": "Write a haiku about spring"},
    {"role": "assistant", "content": "Cherry blossoms bloom..."}
]
response = model.invoke(messages)
```
### Adding context to Human messages
Extra context fields vary by provider, always refer to the model provider's [reference](https://reference.langchain.com/python/integrations/?_gl=1*fi2xh*_gcl_au*MTU4OTcyNjY2LjE3NzM4Njc3MjE.*_ga*MTYxODAxODM1OS4xNzczODY3NzIx*_ga_47WX3HKKY2*czE3NzY5NjM4NDMkbzIwJGcxJHQxNzc2OTYzOTM5JGo2MCRsMCRoMA..)
```python
human_msg = HumanMessage(
    content="Hello!",
    name="alice",  # Optional: identify different users
    id="msg_123",  # Optional: unique identifier for tracing
)
```
### AI message attributes
- `text: string` -> The text content of the message.
- `content: string | dict[]` -> The raw content of the message.
- `content_blocks: ContentBlock[]` ->  The standardized [content blocks](https://docs.langchain.com/oss/python/langchain/messages#message-content) of the message.
- `tool_calls: dict[] | None` -> The tool calls made by the model.Empty if no tools are called.
- `id: string` -> A unique identifier for the message (either automatically generated by LangChain or returned in the provider response)
- `usage_metadata: dict | None` -> The usage metadata of the message, which can contain token counts when available.
- `response_metadata: ResponseMetadata | None` -> The response metadata of the message.

>Other data such as reasoning or citations, can also appear in message content.
### Tool message attributes and context passing
- `content: string` -> The stringified output of the tool call.
- `tool_call_id: string` -> The ID of the tool call that this message is responding to. Must match the ID of the tool call in the [`AIMessage`](https://reference.langchain.com/python/langchain-core/messages/ai/AIMessage).
- `name: string` -> The name of the tool that was called.
- `artifact: dict` -> Additional data not sent to the model but can be accessed programmatically. Useful for storing debugging information, or data for downstream processing **without cluttering the model's context**.

Example of a retrieval tool that returns a passage from a document for a model's reference. The `artifact` contain document identifiers that an application can use to render a page for example:
```python
from langchain.messages import ToolMessage

# Sent to model
message_content = "It was the best of times, it was the worst of times."

# Artifact available downstream
artifact = {"document_id": "doc_123", "page": 0}

tool_message = ToolMessage(
    content=message_content,
    tool_call_id="call_123",
    name="search_books",
    artifact=artifact,
)
```

- Q: What are the four types of messages supported by LangChain?
- A: System, Human (User), AI, and Tool.
- Q: What does each message type represent in LangChain?
- A: Each type represents a participant in the interaction loop between user, system, model, and tools.
- Q: What is the role of a System message?
- A: It provides instructions and context to guide how the model should behave.
- Q: What does a Human (User) message represent?
- A: It represents the input provided by the user.
- Q: What does an AI message contain?
- A: The model’s response, including text, tool calls, and metadata.
- Q: What is a Tool message used for?
- A: It represents the output of a tool call.
- Q: What are the main components of a LangChain message?
- A: Role, content, and metadata.
- Q: What is the purpose of the content field in a message?
- A: It holds the payload sent to the model, such as text, images, audio, or documents.
- Q: What kind of data formats can the content field support?
- A: Strings or structured object lists, including provider-specific formats and multimodal data.
- Q: What are standard content blocks in LangChain?
- A: A provider-agnostic, type-safe representation of message content that works across different providers.
- Q: How can content blocks be provided when creating a message?
- A: By passing a list of typed dictionaries to the `content_blocks` parameter.
- Q: Can content blocks be extracted from provider-specific messages?
- A: Yes, they can be derived from the raw content of messages.
- Q: What is the benefit of using content_blocks instead of raw content?
- A: They provide a standardized and type-safe interface across providers.
- Q: How can you ensure content blocks are stored in message content?
- A: By initializing the model with `output_version="v1"`.
- Q: What is the purpose of LangChain messages in general?
- A: To represent the input and output of models, including content and metadata, in a structured way.
- Q: When should you use a simple text prompt instead of messages?
- A: When you have a single request, don’t need conversation history, and want minimal complexity.
- Q: When should you use message-based prompts?
- A: When managing multi-turn conversations, using multimodal content, or including system instructions.
- Q: What is a potential failure mode when using provider-specific message formats?
- A: It can make it harder to switch providers due to tight coupling.
- Q: How can you mitigate issues with provider-specific message formats?
- A: By creating an abstraction layer over them.
- Q: How do you use messages with a chat model?
- A: By passing a list of messages (e.g., SystemMessage and HumanMessage) to `model.invoke()`.
- Q: Can messages be represented as dictionaries instead of objects?
- A: Yes, using a standard format with `role` and `content`.
- Q: What additional context can be added to a Human message?
- A: Optional fields like `name` and `id` for identifying users and tracing messages.
- Q: What are some key attributes of an AIMessage?
- A: text, content, content_blocks, tool_calls, id, usage_metadata, and response_metadata.
- Q: What does the `tool_calls` attribute in an AIMessage represent?
- A: The tool calls made by the model.
- Q: What is the purpose of `usage_metadata` in an AIMessage?
- A: To store information like token usage when available.
- Q: What is included in a ToolMessage?
- A: Content (tool output), tool_call_id, name, and optional artifact data.
- Q: What is the purpose of the `tool_call_id` in a ToolMessage?
- A: To link the tool response to the corresponding tool call in an AIMessage.
- Q: What is the `artifact` field in a ToolMessage used for?
- A: To store additional data for downstream processing without sending it to the model.
- Q: Why is the artifact field useful?
- A: It allows passing debugging or contextual data without cluttering the model’s input.
- Q: What kind of applications commonly use LangChain messages?
- A: LLM-based applications.
- Q: What components do LangChain messages depend on?
- A: LLMs and LangChain models.
